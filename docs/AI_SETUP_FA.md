# راه‌اندازی دستیار Student OS

دستیار دو مسیر دارد: تحلیل روی دستگاه برای داده‌های تحصیلی ثبت‌شده و پاسخ مولد از سرویس مدل. مسیر دوم تا تنظیم و استقرار سرور فعال نیست. پاسخ محلی یا پاسخ ساختگی تست، اثبات اتصال مدل آنلاین نیست. هیچ درخواست Gemini در مسیر جدید وجود ندارد. کلاینت به تابع جدید `generateAcademicAssistantReply` وصل می‌شود و به تابع قدیمی برگشت نمی‌کند؛ بنابراین APK جدید پیش از استقرار سرور هم مسیر قدیمی را استفاده نمی‌کند.

## مسیر سادهٔ پیشنهادی: یک کلید OpenAI برای کل برنامه

مدل پیش‌فرض سرور `gpt-5.4-mini-2026-03-17` است و متن و تصویر را پشتیبانی می‌کند. با ثبت فقط `AI_API_KEY`، آدرس، نام مدل و پشتیبانی تصویر پیش‌فرض آماده‌اند؛ نیازی به تنظیم مدل در گوشی نیست. این انتخاب بر اساس [مستندات رسمی مدل](https://developers.openai.com/api/docs/models/gpt-5.4-mini) بررسی‌شده در 2026-10-25 است. تغییر سرویس یا مدل همچنان از env سرور ممکن است.

کاربر برنامه کلید نمی‌دهد، حساب OpenAI نمی‌سازد و برای دستیار وارد حساب جداگانه نمی‌شود. برنامه هنگام اولین درخواست آنلاین یک نشست امنِ مخصوص دستیار را خودکار برقرار می‌کند. این نشست در همان پروژهٔ Firebase و در یک FirebaseApp مجزا قرار دارد؛ حساب مهمان، Firebase یا بک‌اند فعلی دانشجو تغییر نمی‌کند. سهمیه به شناسهٔ همین اتصال روی نصب برنامه تعلق دارد. بازکردن صفحهٔ دستیار به‌تنهایی نشست آنلاین ایجاد نمی‌کند.

مالک باید یک‌بار Firebase موجود را برای Functions، Anonymous Authentication و App Check آماده کند و حساب API دارای اعتبار مصرف داشته باشد. تنها کلید API بدون دسترسی استقرار یا آماده‌بودن Firebase، سرویس عمومی ایجاد نمی‌کند. این کارها مربوط به مدیر برنامه است؛ کاربران هیچ‌کدام را انجام نمی‌دهند. اشتراک ChatGPT به‌تنهایی اعتبار API نیست.

از ریشهٔ مخزن، روی رایانهٔ مدیر:

```sh
npm --prefix functions ci --ignore-scripts --no-audit --no-fund
npm --prefix functions exec -- firebase login
npm --prefix functions run ai:setup -- --check
npm --prefix functions run ai:setup -- --deploy
```

`--check` فقط برنامهٔ تنظیم را نشان می‌دهد و چیزی نمی‌نویسد. `--deploy` پروژه را از google-services.json می‌خواند، تنظیمات غیرمحرمانهٔ OpenAI را با حفظ تنظیمات پرداخت و سقف‌های موجود ثبت می‌کند، کلید را با ورودی امن Firebase CLI به Secret Manager می‌فرستد و فقط دو تابع دستیار را مستقر می‌کند. مقدار کلید وارد argv یا APK نمی‌شود. در صورت نیاز به پروژهٔ دیگر `--project PROJECT_ID` را صریح بدهید. نسخهٔ فعلی مخزن به پروژهٔ `dani-87c77` اشاره می‌کند.

پیش از اجرای استقرار، Anonymous Authentication و تنظیم App Check بازار را طبق بخش پایین در کنسول مالک آماده کنید. موفقیت فرمان استقرار، اثبات دریافت پاسخ مدل یا تأیید دستگاه نیست؛ آزمون واقعی بعد از ثبت کلید لازم است.

## رفتار قابل استفاده بدون سرویس مدل

اولویت تکلیف‌ها، پیشنهاد هفت‌روزه با بودجهٔ دقیقه‌ای، مرور امتحان، بررسی نمره‌های واقعاً ثبت‌شده، حضور و غیاب و جلسات کلاس از اطلاعات خود دانشجو محاسبه می‌شوند. زمان آزاد، جزوه و قوانین دانشگاه حدس زده نمی‌شوند. تکمیل تکلیف به انتخاب روشن و تأیید نیاز دارد؛ تکلیف تکراری نیز فقط یک رخداد بعدی می‌سازد. حالت «فقط تحلیل روی دستگاه» هیچ درخواست جدیدی به مدل ارسال نمی‌کند. توقف انتظار، درخواست آغازشده در سرور را لزوماً لغو نمی‌کند.

همهٔ حالت‌های دستیار برای کاربر رایگان‌اند. سقف‌های روزانه برای کنترل مصرف سرور هستند و به اشتراک وابسته نیستند. هزینهٔ سرویس مدل و Firebase بر عهدهٔ صاحب برنامه است.

## اطلاعات لازم از صاحب پروژه

۱. شناسهٔ پروژهٔ Firebase موجود و دسترسی استقرار روی همان پروژه؛ پروژهٔ جدید جایگزین داده‌ها یا احراز هویت فعلی نمی‌شود.
۲. سرویس دارای API سازگار با Chat Completions، آدرس HTTPS و نام دقیق مدل مجاز در آن حساب. OpenAI با مدل آمادهٔ پیش‌فرض انتخاب شده؛ تغییر مدل در سرور اختیاری است.
۳. کلید API فقط در Secret Manager با نام `AI_API_KEY` ثبت شود. کلید را در گفتگو، گیت، APK یا فایل تنظیمات عمومی نفرستید.

## مراحل تنظیم روی دستگاه مدیر

- فایل `functions/.env.example` را به `functions/.env.PROJECT_ID` کپی کنید ؛ مدل و آدرس OpenAI از پیش تنظیم شده‌اند و فقط برای تغییر سرویس نیاز به ویرایش دارند. برای سرویس‌هایی که لازم دارند `AI_TOKEN_PARAMETER=max_tokens` بگذارید.
- از ریشهٔ پروژه: `firebase functions:secrets:set AI_API_KEY --project PROJECT_ID`؛ مقدار را در ورودی امن دستور وارد کنید.
- Anonymous Authentication را در Firebase Authentication فعال کنید. نشست مخصوص دستیار به‌صورت خودکار و مستقل از حساب اصلی ساخته می‌شود؛ ورود فعلی دانشجو جایگزین نمی‌شود و داده‌های مهمان روی دستگاه می‌ماند.
- App Check را برای پکیج `com.aistudio.studentos.appvzk` و گواهی تولید تنظیم کنید. SHA-256: `a335e71031ec78a7961656b2c36d8c53abcb3bdc28e265998cf6053fb94eb950`.
- برای توزیع انحصاری خارج از Google Play مانند بازار، طبق تنظیمات پیشرفتهٔ رسمی Play Integrity، الزام `PLAY_RECOGNIZED` و `LICENSED` مناسب این توزیع نیست؛ سطح `DEVICE_INTEGRITY` را مطابق راهنمای رسمی انتخاب کنید. App Check را در کد خاموش نکنید. برای بیلد دیباگ، توکن Debug App Check مربوط به FirebaseApp مخصوص دستیار باید در کنسول همان پروژه ثبت شود؛ ممکن است با توکن اپ پیش‌فرض فرق داشته باشد.
- بعد از بررسی تنظیمات، مدیر می‌تواند فقط دو تابع جدید را مستقر کند: `firebase deploy --only functions:getAcademicAiStatus,functions:generateAcademicAssistantReply --project PROJECT_ID`. این مستند به معنی انجام استقرار نیست.
- خواندن تصویر با OpenAI پیش‌فرض فعال است؛ با `AI_VISION_ENABLED=false` می‌توان آن را خاموش کرد. برای سرویس دیگر فقط با مدل پشتیبان تصویر و `AI_VISION_ENABLED=true` فعال کنید؛ در صورت نیاز `AI_VISION_MODEL` را هم تعیین کنید.
- سقف پیش‌فرض هر شناسه در روز تهران ۲۰ پاسخ و ۳ تصویر، سقف کل ۵۰۰ درخواست است. شکست قابل تشخیص سرویس سهمیه را برمی‌گرداند. توقف فرایند سرور ممکن است رزرو درخواست ناتمام را تا پایان روز نگه دارد. روی هزینهٔ ارائه‌دهنده نیز سقف بودجه تنظیم کنید. فیلد `expiresAt` به‌تنهایی حذف خودکار Firestore را فعال نمی‌کند؛ برای پاک‌سازی فراداده، TTL دو مجموعهٔ `aiUsage` و `aiRequests` را در کنسول تنظیم کنید.

## تأیید واقعی

`npm --prefix functions test` فقط آزمون قراردادها با پاسخ شبیه‌سازی‌شده است. برای یک درخواست واقعی با دادهٔ مصنوعی، متغیرهای بالا را در محیط امن مدیر قرار دهید و `AI_LIVE_TEST=1 node functions/scripts/probe-ai.js` اجرا کنید. این درخواست می‌تواند هزینه داشته باشد؛ متن پاسخ یا کلید چاپ نمی‌شود. سپس روی APK امضاشدهٔ تولید، با نصب بازار و یک نشست مهمان، وضعیت سهمیه، پاسخ فارسی، قطع اینترنت و تلاش دوباره را بررسی کنید. آزمون مستقیم ارائه‌دهنده، تأیید عبور از App Check یا صحت استقرار Firebase نیست.

متن پرسش و اطلاعات محدود درس‌ها، تکلیف‌ها، امتحان‌ها و مطالعه در حالت مدل برای پاسخ‌گویی به ارائه‌دهنده ارسال می‌شوند؛ شمارهٔ دانشجویی و یادداشت خصوصی پروفایل به‌طور خودکار در زمینه قرار نمی‌گیرند. خود کاربر ممکن است اطلاعاتی را در پرسش بنویسد. سرور متن گفتگو را در Firestore ذخیره نمی‌کند. شرایط نگهداری دادهٔ سرویس انتخاب‌شده باید بررسی شود. سابقهٔ گفتگو در برنامه محدود است و برای بازسازی صفحه نگهداری می‌شود؛ آرشیو دائمی گفتگو ارائه نشده است.
