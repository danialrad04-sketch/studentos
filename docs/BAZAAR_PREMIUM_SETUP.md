# Student Pro / Cafe Bazaar — 2.3.0

این نسخه قرارداد پرداخت را به Firebase Functions وصل می‌کند. هیچ کلیک، کد داخلی، توکن تأییدنشده یا پاسخ صرفاً موفق SDK دسترسی پولی ایجاد نمی‌کند. ریلیز منتشرشدهٔ 2.2.0 تغییر نمی‌کند.

## قیمت‌گذاری

هدف مالک پروژه: **دریافتی پس از کسورات بازار حداقل ۱۵۰٬۰۰۰ تومان برای هر ماه**. این مبلغ سود خالص پس از هزینهٔ AI، Firebase، پشتیبانی یا مالیات درآمد نیست.

منابع رسمی خوانده‌شده در 2026-10-05:

- https://developers.cafebazaar.ir/fa/guidelines/financial/developers-share (خود صفحه آخرین به‌روزرسانی ۱۴۰۳/۰۱/۲۶ را اعلام می‌کند)
- https://developers.cafebazaar.ir/fa/guidelines/financial/calculate-shaparak-fee

راهنمای منتشرشده سهم توسعه‌دهنده را برای فروش سالانه کمتر از یک میلیارد تومان ۸۵٪ و بیش از آن ۷۰٪ معرفی می‌کند. مالیات ارزش افزوده ابتدا از قیمت نهایی کسر می‌شود؛ مثال‌های صفحه از نرخ ۱۰٪ استفاده می‌کنند. کارمزد تراکنش‌های کمتر از ۶۰۰ هزار تومان در همین راهنما ۱۲۰ تومان است؛ برای پرداخت مستقیم بازار کارمزد بانکی صفر اعلام شده است. این صفحات تأیید مستقل نرخ مالیاتی سال ۱۴۰۵ یا شرایط قرارداد این ناشر نیستند؛ پیش از فروش گزارش مالی و قرارداد جاری پیشخان را بررسی کنید.

فرمول نمونه: `net = gross / (1 + VAT) * developerShare - bankFee`.

| حالت نمونه | قیمت نهایی دانشجو | دریافتی تقریبی |
|---|---:|---:|
| ماهانه، سهم ۸۵٪، VAT=۱۰٪، کارمزد=۱۲۰ | ۱۹۴٬۵۰۰ تومان | ۱۵۰٬۱۷۵ تومان |
| سه‌ماهه، همان فرض‌ها | ۵۸۳٬۵۰۰ تومان | ۴۵۰٬۷۶۶ تومان |
| ماهانه، سهم ۷۰٪، همان VAT/کارمزد | ۲۳۶٬۰۰۰ تومان | ۱۵۰٬۰۶۲ تومان |

با فرض صرفاً ۱۵٪ سهم بازار بدون سایر کسورات، ۱۷۶٬۴۷۱ تومان کافی است؛ برای هدف واقعی دریافتی بعد از مالیات/کارمزد این محاسبه کامل نیست. اگر VAT یا سهم قرارداد فرق دارد، قیمت `PREMIUM_MONTHLY_PRICE_TOMAN` و قیمت هر دو محصول در پیشخان را هم‌زمان تغییر دهید. کلاینت قیمت محلی‌شدهٔ SDK را با قیمت کاتالوگ تطبیق می‌دهد و در صورت تفاوت خرید را آغاز نمی‌کند.

## پیشخان بازار

در همان برنامه و با همان package `com.aistudio.studentos.appvzk` دو محصول از نوع **اشتراک** ایجاد کنید، نه کالای مصرفی:

| SKU آماده‌شده در کد | دورهٔ محصول در بازار | قیمت پیشنهادی در فرض بالا |
|---|---|---:|
| `studentos_pro_monthly` | یک ماه | ۱٬۹۴۵٬۰۰۰ ریال |
| `studentos_pro_quarterly` | سه ماه | ۵٬۸۳۵٬۰۰۰ ریال |

دوره و تمدید باید در پیشخان دقیقاً مطابق متن برنامه تنظیم شوند. تاریخ فعال‌بودن از API بازار دریافت می‌شود؛ برنامه با جمع‌کردن ۳۰ روز یا تکیه بر `autoRenewing` دسترسی اعطا نمی‌کند. پیش از تأیید پرداخت، صفحهٔ بازار مبلغ و شرایط را نشان می‌دهد. مدیریت تمدید از حساب بازار انجام می‌شود.

در قسمت پرداخت درون‌برنامه‌ای، کلید **عمومی RSA** برنامه را دریافت کنید. این کلید، کلید خصوصی امضای APK/AAB نیست. در قسمت «API پیشخان بازار» با حساب ناشر، توکن برنامه را دریافت کنید؛ توکن محرمانه است و فقط در سرور ذخیره می‌شود.

مستندات فنی اجراشده:

- https://github.com/cafebazaar/Poolakey/releases/tag/2.2.0
- https://developers.cafebazaar.ir/fa/guidelines/in-app-billing/api/setting-up-new
- https://developers.cafebazaar.ir/fa/guidelines/in-app-billing/api/postman-and-bazaar-api-new
- https://developers.cafebazaar.ir/fa/guidelines/in-app-billing/api/active-subscription

هدر جدید `CAFEBAZAAR-PISHKHAN-API-SECRET` به endpoint `active-subscriptions/<token>/` فرستاده می‌شود؛ این endpoint توکن تمدید را نیز می‌پذیرد. توکن اشتراک با AES-256-GCM ذخیره و مالکیت شناسهٔ پایدار `linkedSubscriptionToken` در تراکنش به یک حساب متصل می‌شود. امضای RSA رسید، package، SKU، وضعیت خرید و developerPayload حساب نیز بررسی می‌شوند. محصول اشتراکی مصرف نمی‌شود.

## Firebase موجود

از حسابی که همین پروژهٔ Firebase برنامه را مدیریت می‌کند استفاده کنید. فایل google-services.json همان پروژه و امضای تولید موجود حفظ می‌شوند. Functions در `us-central1` فراخوانی می‌شوند؛ اگر منطقهٔ استقرار قبلی متفاوت است مقدار `PREMIUM_FUNCTIONS_REGION` در Gradle را با منطقهٔ استقرار یکسان کنید.

چهار مقدار زیر فقط در Firebase Secret Manager ثبت می‌شوند؛ آن‌ها را در چت، مخزن، فایل `.env` برنامه یا صفحهٔ حساب کاربران وارد نکنید:

```sh
npx firebase-tools@15.32.1 functions:secrets:set BAZAAR_API_SECRET --project YOUR_PROJECT_ID
npx firebase-tools@15.32.1 functions:secrets:set BAZAAR_RSA_PUBLIC_KEY --project YOUR_PROJECT_ID
npx firebase-tools@15.32.1 functions:secrets:set BILLING_TOKEN_ENCRYPTION_KEY --project YOUR_PROJECT_ID
npx firebase-tools@15.32.1 functions:secrets:set GEMINI_SERVER_API_KEY --project YOUR_PROJECT_ID
```

کلید رمزگذاری باید ۳۲ بایت تصادفی به صورت Base64 باشد. این کلید را پس از ثبت خریدها خودسرانه عوض نکنید؛ چرخش آن نیاز به رمزگذاری مجدد توکن‌های ذخیره‌شده دارد.

`functions/.env.example` را به `functions/.env.YOUR_PROJECT_ID` کپی کنید. فروش ابتدا `false` می‌ماند. مدل فعلی پیش‌فرض سرور `gemini-3.5-flash-lite` است؛ مدل و هزینه/ظرفیت آن را از https://ai.google.dev/gemini-api/docs/models و حساب Google بررسی کنید. کلید Google هرگز به کلاینت برگردانده نمی‌شود. Firebase Functions و API مدل باید روی همین پروژه فعال و حساب صورتحساب آماده باشند.

```sh
npm --prefix functions ci
npx firebase-tools@15.32.1 deploy --only functions,firestore:rules --project YOUR_PROJECT_ID
```

App Check برای توابع جدید اجباری است. **آن را برای حل خطای نصب بازار خاموش نکنید.** تنظیمات Play Integrity همین package و certificate را برای انتشار خارج از Google Play بررسی کنید؛ الزام‌های PLAY_RECOGNIZED و LICENSED باید با مسیر انتشار بازار سازگار باشند. ثبت Debug Token فقط برای build آزمایشی است. راهنمای رسمی: https://firebase.google.com/docs/app-check/android/play-integrity-provider

TTL روی فیلد `expiresAt` در `aiRequests` و `aiUsage` فعال کنید تا داده‌های حسابداری سهمیه حذف شوند. محتوی گفت‌وگو، عکس و پاسخ در این مجموعه‌ها ذخیره نمی‌شود. ارسال عکس تنها پس از انتخاب و تأیید کاربر است. ساعت بازنشانی سهمیه نیمه‌شب تهران است. خطای provider سهمیهٔ رزروشده را برمی‌گرداند؛ سقف درخواست/پاسخ و timeout و maxInstances محدودند. خریدهای بازار هنگام دریافت وضعیت/درخواست AI، پس از حداکثر پنج دقیقه دوباره بررسی می‌شوند؛ این نسخه ادعای webhook لحظه‌ای بازپرداخت ندارد.

## پیش از فعال‌سازی فروش

با حساب آزمایشی همان Student OS و نسخهٔ امضاشده روی دستگاه دارای بازار:

1. پاسخ واقعی آنلاین بدون API key کاربر، سهمیه، خطای شبکه و بازنشانی روز را امتحان کنید.
2. امضای APK را با نسخهٔ قبلی تطبیق دهید و App Check نسخهٔ نصب‌شده از بازار را تأیید کنید.
3. محصولات و قیمت SDK را بررسی کنید. خرید، لغو صفحهٔ خرید و خطای پرداخت باید وضعیت‌های درست نشان دهند.
4. بعد از خرید، هم metadata سرور و هم پاسخ ابزار پرو را بررسی کنید. قطع شبکه بعد از پرداخت، بازگشایی، بازیابی، حذف و نصب و ورود با حساب دیگر را تست کنید.
5. پایان دوره، تمدید و عودت خرید را در محیط آزمایشی بازار بررسی کنید. API ناموفق نباید پرمیوم بسازد.
6. سپس `PREMIUM_SALES_ENABLED=true` را در env سرور تنظیم و دوباره Functions را deploy کنید. این سوئیچ بدون Secrets لازم فروش را فعال نمی‌کند.

تست‌های repo، رسیدهای امضاشدهٔ ساختگی و provider شبیه‌سازی‌شده به کار می‌برند؛ آن‌ها جای خرید واقعی، انتشار در پیشخان یا استقرار Firebase را نمی‌گیرند. هیچ توکن API بازار/Google و دسترسی استقرار Firebase در این نشست ارائه نشده است. حساب‌های fallback سرور Node در این مرحله مسیر خرید Firebase ندارند؛ برای خرید باید با حساب Firebase وارد شوند و خرید به همان UID متصل می‌شود.
